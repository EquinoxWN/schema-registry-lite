# Quality check, 2026-11-01

The ten engineering rules, checked against the code on `main`, with the evidence. Run on Windows 11
with Python 3.14 in the repository's `.venv`.

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Assume every call can fail | fixed | SQLite connections use a 10 s busy timeout and every connection is closed in `finally` (`store.py`). Two gaps in the HTTP server: the handler had no socket timeout, so a client that sent half a request held a worker thread forever; it now has `timeout = READ_TIMEOUT` (30 s), test `test_a_stalled_client_is_disconnected`. The catch-all `except Exception` returned 500 but dropped the error; it now prints the traceback to stderr (`test_unexpected_errors_are_500_and_logged`). |
| 2 | Writes safe to retry | pass | Registering the same schema again returns the existing ID and version (normalized form, `UNIQUE` on `schemas.normalized`, `test_registering_the_same_schema_again_is_idempotent`). `PUT /config` is an upsert. Mutant S8 (no idempotency) is killed. |
| 3 | No race conditions | fixed | Registration runs in `BEGIN IMMEDIATE`, so version numbers never collide (12 concurrent registrations get 1 to 12). But `register` read the compatibility mode on a separate connection before the transaction: a mode change between that read and the write could let a schema through under the old mode. The mode is now read inside the transaction (`store._mode`). |
| 4 | Don't trust the clock | pass | No time is read or stored; ordering is by version number. |
| 5 | Read before changing | pass | No environment variables are read. CLI options (`--db`, `--host`, `--port`) are in the README. Every path in the README exists. |
| 6 | Never break compatibility | pass | The SQLite schema uses `CREATE TABLE IF NOT EXISTS` and did not change. The REST paths and Confluent error codes are unchanged; a negative `Content-Length` now gets 400/40001, which was a hang before. |
| 7 | One source of truth | pass | SQLite is the only store; no caches. Versions in README and `pyproject.toml` agree. |
| 8 | Small changes, no secrets, validate input | fixed | `git grep -iE "(api[_-]?key|secret|token|password)\s*[:=]"`: no matches. Bodies were capped at 1 MiB, but a negative `Content-Length` made `rfile.read(-1)` wait for the client to close the connection, and a non-numeric one raised a 422 by accident. `Content-Length` must now be digits, else 400 (`test_negative_content_length_is_refused_not_read_to_eof`). Subjects, schemas, modes and IDs were already validated. No new dependency. |
| 9 | Tests that can actually fail | fixed | No `skip`, `xfail` or tautologies; warnings are errors. Mutation check below: 1 of 13 survived and now has a test that kills it. |
| 10 | Re-verify | pass | `ruff check .`: `All checks passed!`; `ruff format --check .`: clean; `mypy`: `Success: no issues found in 13 source files`; `pytest -q`: `98 passed`; `pip-audit`: `No known vulnerabilities found`; `audit_repo.py`: OK. CI on push. |

## Tests added (94 -> 98)

The four tests named in the table above. The mode-read race (rule 3) has no deterministic test: it
needs a second writer between two statements; the fix moves the read under the same `BEGIN
IMMEDIATE` lock as the write.
