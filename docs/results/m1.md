## Analyze

- **Defect found by the bench:** under BACKWARD a registration should compare with the latest
  version only, but its time grew from 16 to 67 ms over 200 versions. Root cause: `register` parsed
  every earlier version before the mode decided which ones to compare. Fix: `_needed` parses only
  the versions the mode uses (none, the latest, or all for TRANSITIVE). BACKWARD's late median fell
  to 33 ms; the remaining growth comes from the schema itself (201 fields at the end) and the
  history query. FULL_TRANSITIVE still grows with history, as it must compare with every version.
- **Defect found by a test:** the first version of the oversized-body test sent a real 1 MiB body;
  the server answered 413 and closed while the client was still sending, so the client saw a reset.
  The server now marks the connection to close after a 413, and the test sends only a forged
  50 MiB Content-Length, which is the real attack shape; the body is never read.
- **Demo correction:** a step meant to show FULL_TRANSITIVE re-registered v1, which (correctly)
  returned version 1 without a check; it was replaced by a change that only the transitive check
  rejects.
